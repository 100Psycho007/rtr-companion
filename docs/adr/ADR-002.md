# ADR-002 — BLE Permissions Declared in `ble-core` Manifest

## Status

Accepted

## Context

Android BLE requires multiple permissions, and their exact set depends on API level:
- API ≥ 31: `BLUETOOTH_SCAN` + `BLUETOOTH_CONNECT`
- API ≤ 30: `BLUETOOTH` + `BLUETOOTH_ADMIN` + `ACCESS_FINE_LOCATION`

These permissions must appear in the final merged manifest. They could be declared in
the `app` module or in `ble-core`.

## Decision

Declare all BLE permissions in `ble-core/src/main/AndroidManifest.xml`. They are
automatically merged into any consuming app's manifest by the Android Gradle Plugin.

## Alternatives Considered

- **Declare in `app/AndroidManifest.xml`** — Simpler, but means any app that wants to
  use `ble-core` as a library must manually add all permissions. Error-prone.
- **Declare in both** — Redundant and confusing.

## Reasoning

The `ble-core` module owns BLE operations. It should own the permissions that enable
those operations. This is the standard pattern for Android library modules.

## Consequences

- **Positive:** Any future app consuming `ble-core` automatically gets all required
  BLE permissions without extra configuration.
- **Negative:** Minor — the app manifest doesn't make its BLE dependency explicit at
  a glance. Mitigated by the comment in `app/AndroidManifest.xml`.
