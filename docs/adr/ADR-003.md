# ADR-003 — Dual `onCharacteristicChanged` Implementation

## Status

Accepted

## Context

Android API 33 (Tiramisu) deprecated `onCharacteristicChanged(BluetoothGatt, BluetoothGattCharacteristic)`
and introduced a new override `onCharacteristicChanged(BluetoothGatt, BluetoothGattCharacteristic, ByteArray)`
that delivers the value as a separate parameter, avoiding a race condition where the
characteristic value could be overwritten before the callback ran.

The project targets `minSdk = 29` and `compileSdk = 35`.

## Decision

Implement both overrides in `RtrGattManager.BluetoothGattCallback`:
1. The deprecated override (suppressed with `@Suppress("DEPRECATION")`) for API < 33
2. The new override for API ≥ 33

Both delegate to the same `handlePacket(ByteArray)` function.

## Alternatives Considered

- **Only implement the deprecated override** — Works on all API levels but triggers
  lint warnings and is technically incorrect on API 33+ (race condition risk).
- **Only implement the new override** — Does not get called on API < 33; packets would
  be silently lost.
- **Runtime API check inside the deprecated override** — Overly complex; the dual
  override approach is the Android-recommended pattern.

## Reasoning

The Android documentation explicitly recommends implementing both for apps with
`minSdk < 33` and `compileSdk >= 33`. The dual override is idiomatic.

## Consequences

- **Positive:** Correct behaviour on all supported API levels (29–35). No race condition
  on API 33+.
- **Negative:** Minor code duplication. Mitigated by both overrides delegating to the
  shared `handlePacket()` function.

## Review Trigger

When `minSdk` is raised to 33 or above, remove the deprecated override.
